project/
├── src/
│   ├── index.html
│   └── main.ts
├── dist/
│   └── main.js
├── package.json
└── tsconfig.json

Minimal compiler configuration

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "strict": true,
    "rootDir": "./src",
    "outDir": "./dist"
  },
  "include": ["src/**/*"]
}

TypeScript’s documentation describes tsconfig.json as the project configuration boundary. The compiler’s strict option enables the family of strict type checks. Modern browser applications can use standard ECMAScript modules; TypeScript’s module documentation explains that module behavior is ultimately determined by the host, such as the browser and the web server serving the files.

Sources: TypeScript tsconfig.json, Compiler options, Modules.

Frequently Asked Questions

Do I need JavaScript before starting?

No. The first seven modules intentionally teach programming ideas in a JavaScript-compatible way before the course asks you to care deeply about TypeScript’s type system.

Do I need Node.js?

No for the learning path. The course uses the TypeScript compiler and a browser. A package manager may be convenient for installing the TypeScript compiler, but Node-specific application development is deliberately outside the course scope.

Why not start with interfaces immediately?

Because interfaces are much easier to understand after you already know objects, arrays, functions, and the kind of data a program needs to model.

Is this an official INF.04 course?

No. It is an original course designed around the requested browser-programming focus. Use the latest official CKE information for exact examination rules, dates, and requirements for your session.

How should I use the solutions?

Attempt first. When you open a solution, compare the idea and structure, then close it and rewrite your own version without copying line for line.
